## Boundary and source/policy status

The new `runoff_routing.monte_carlo_plan` API makes no routing calls, uses no mutable/global pseudorandom state and does not fabricate an effective hydrograph. Current `python-cmd/cmd-6.44` remains the temporary execution default; this sampler has no engine selection and is independently reusable with the intended later `python` engine.

This change intentionally supplies **no purported RORBwin empirical-loss CDF, native RNG, automatically inferred TP frequency edges, or unchecked joint loss dependence**. The explicit loss inverse, normal-coordinate z-linear depth interpolation and RNG policy implement the staged [#145 PR #158](https://github.com/Chain-Frost/python-runoff-routing/pull/158) and [corrective #170](https://github.com/Chain-Frost/python-runoff-routing/pull/170) `monte-carlo-statistics/1` project decisions. The sampler enforces the named `conditional-tp-on-aep__independent-storm-il-v1` law and fails closed on unimplemented correlated/conditional loss profiles; a caller cannot label an arbitrary method reviewed. This project-method decision is distinct from native/statistical qualification and still does not demonstrate RORBwin parity and does **not** demonstrate RORBwin parity, qualify real catchment sources, or complete engine integration. The existing BoM/ARR source readers are reused through `ifd_from_bom` and `ifd_from_arr` (not reimplemented); EY and ARI are not silently mapped to AEP. The `source_id`/SHA-256 inputs must be bound to the verified original source bytes by the caller. `ifd_from_bom` requires depth in mm and exact duration; no implicit intensity conversion.

## Version 1 schema and handshake

The immutable plan manifest is JSON. A plan records `schema_version=1`, full `spec`, `plan_id`, `population_id`, optional `parent_plan_id` and `domain`. The `spec` records the explicit `policy` ID/version/status, scenario, duration (minutes), source SHA-256 map (`ifd`, `temporal_patterns`, optional `initial_loss`), RNG algorithm/derivation/root seed, strata, IFD depth table/interpolation, conditionally eligible TP `EventID`/source order/selection probabilities, storm IL mode, fixed parameters with units, ARF/preburst/joint policy IDs and the within-stratum transform. Every stratum stores exact AEP-fraction bounds, probability mass and sample count (zero may represent explicitly unsampled interior mass). The `domain` records modelled interior mass, allocated and zero-allocation interior mass and both missing tails; it is never implicitly rescaled to probability one.

Sample records are UTF-8 NDJSON with `plan_id`, `sample_id`, stratum/index, scenario/duration, selected annual-exceedance **fraction**, `gross_ifd_depth_mm`, TP bin/original `EventID`/source order, primitive loss/TP uniforms, source-inverted storm IL ratio/millimetres and `event_probability_weight`. Storm IL is **storm** (pre-preburst) initial loss; applying source-specific ARF, preburst, storm hyetograph construction and routing is exclusively #149's responsibility. A manifest and record together provide the effective B-stage draw without an RNG call. Results and flow-frequency quantiles are not stored in the plan.

AEP is rainfall exceedance probability `p` in (0, 1), *not percent*, EY or ARI. Strata are contiguous disjoint `[lower,upper)` ranges (the final upper bound is closed for lookup); draws use a HMAC-SHA256-keyed open-interval 53-bit uniform in cumulative AEP probability mass: `p = lower + (upper-lower)*U`. Normal-coordinate bins can be constructed with `normal_coordinate_strata`, but a Normal coordinate does **not** mean rainfall depth is Normally distributed. Each original eligible TP member has an explicit nonnegative probability, with total one within its conditional bin (zero-weight members remain identified but never selected). Selection chooses the first cumulative weight **strictly greater** than its uniform; a value exactly equal to an internal boundary selects the following member. Empirical loss maps an explicitly source-identified nonexceedance-probability quantile table to a median-scaled **storm** IL; no default CDF is inferred.

The RNG profile implements draft #145's `hmac-sha256-53-v1`, derivation `canonical-json-domain-separated-v1`. The key is the unsigned 64-bit root seed as **eight big-endian bytes**; the message is canonical sorted-key compact JSON with a namespace/version, population digest, adopted policy, immutable source identities, scenario, duration, stratum bounds/ID, within-stratum ordinal and distinct purpose (`rainfall`, `tp`, `loss`). The message excludes current stratum allocation, plan revision and worker/chunk order. The high 53 bits of the first eight HMAC-SHA256 digest bytes, mapped to their open-cell midpoint `(2*k+1)/2**54`, define each uniform. Same-source/seed runs are independent of chunk order, worker scheduling and global `random` state. **Same integer seed in RORBwin and Python does not imply equal native draws.** This HMAC stream is used for reproducibility, not a claim that a given sampled parameter distribution is correct.

`population_id` hashes the canonical numerical spec **excluding only per-stratum sample counts**; `plan_id` hashes the complete numerical spec including those counts. The optional parent pointer records provenance but is excluded from the computational identity; an extension and a directly generated identical larger allocation therefore share `plan_id`. Sample IDs contain population digest, source stratum ID and within-stratum ordinal, never the revision hash. Increasing a stratum from `n_h` to `n'_h` leaves old logical IDs/primitive draws unchanged while all records for that stratum receive **new** `w_h/n'_h` weights. An old revision's records cannot be read as a new revision; #149 must reuse prior event computations by stable logical IDs and **reaggregate all weights** under the latest immutable plan.

`write_sample_plan` writes a no-overwrite `.plan.json` and streaming `.samples.jsonl` pair. `iter_stratum_samples` supports arbitrary finite chunks, `iter_saved_sample_records` streams validated replay (O(n) sample-index identities, not O(n) hydrographs), and `read_sample_records` is the bounded convenience reader for small plans. A complete reader rejects absent records, invalid positive-weight members, duplicates, source-derived numerical changes, incompatible plan/weight/revision IDs and malformed JSON. The record's `plan_id` must match the complete current revision; event result rows must separately bind that plan and engine identity.

## November 16 closeout amendment for #146

Independent #150 review identified a missing joint-law guard: a free-text `joint_policy` could assert correlated or conditional loss while the implementation actually drew it independently. The sampler now accepts **only** `conditional-tp-on-aep__independent-storm-il-v1` with the explicit user-supplied choice and otherwise raises `SamplePlanError`; a separate conditional-law profile requires its own reviewed implementation. The reviewed *project method* status is permitted only with exactly `monte-carlo-statistics/1`; no status asserts native RORBwin compatibility. The previously reported z-linear IFD and 64-bit-keyed HMAC mismatches were already fixed, with an independently pinned HMAC digest control.

Local Python 3.13.5/Linux focused source tests: **39 passed**. A disposable isolated **B-module-only wheel** with the same source bytes was installed outside the checkout and verified using `python -I` and the complete focused suite (**39 passed**). This local wheel is *not* a full repository source/wheel parity receipt: its package deliberately contains only the B module. The full source/installed-wheel CI and independent final interface review must be checked separately on the exact PR head before staging, and the parent #9 still owns real-model/native acceptance.

The final audit also identified a persisted-schema bound failure: a permitted 128-character stratum ID would make a plaintext-based logical sample ID exceed the 128-character sample-field bound. Logical sample IDs now hash **the full population identity**, stratum ID, ordinal and identity-version to a 64-character SHA-256 string prefixed `mc:`, independent of plan allocation and revision. The new 128-character-stratum regression proves source distinction and round-trip replay. This identity revision affects only draft #146 software, not admitted prior published plans. The local B-module-only wheel SHA-256 is `c153600038b35b3acd17cf36c0ec5c874923153b52bf451ef205fb25187ee9e1` (Python 3.13.5 Linux; not the full public repository wheel). Full Windows source/wheel CI and stage merge receipts must be appended after execution.

The #145 adopted, independently calculated three-purpose HMAC test vector (root seed 42, fixed synthetic policy/source identity and full population ID) is now asserted literally alongside the independent plan-derived HMAC vector. The final strict-typing correction casts the detached reviewed-policy object in the tests; it does not change sampler arithmetic or revision identity.


## 16 November 2026: post-merge numeric-context and manifest persistence corrections

The original #146 software PR #164 was correctly staged, but later audit identified two specific defects in the merged sampler: inherited caller Decimal precision/rounding/traps could change or reject stochastic draws, interpolation and plan mass arithmetic, and the manifest writer could create files larger than the reader's 2 MiB bound. Neither defect requires new sampling distributions, event routing, weighted reporting, GUI work or native experiments.

The follow-up fix pins an isolated 60-digit, ROUND_HALF_EVEN Decimal context for all sampler arithmetic, including stratum-width validation, source AEP conversion, domain/stratum mass, HMAC uniform conversion, IFD/loss inverse, draw weights and persisted replay verification. The seed, byte-level HMAC message, source bindings and sampling method are **unchanged**; ordinary default-context numerical results are retained. The writer now measures actual UTF-8 bytes of the intended human-inspectable manifest and rejects oversize plans *before creating either file*; exactly-at-limit plans remain readable. Input and ledger size protections are unchanged.

The original behaviour was independently reproduced locally: under a deliberately hostile Decimal context (precision 5, ROUND_DOWN, a small exponent range and trapped Inexact), the original z-linear interpolation raises decimal.Inexact; with a reduced test manifest limit, the original writer silently writes a file its reader refuses. Both new controls pass after correction. Locally mirrored Python 3.13.5/Linux focused suite: **36 passed** (34 previously represented controls plus two new defects). This local mirror is **not** the exact GitHub head or a complete installed-wheel acceptance record. Exact-head Windows source/wheel regression and independent review remain required before merging this follow-up into draft staging #151; original parent #9 scientific/native acceptance remains open.
