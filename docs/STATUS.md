## Interpretation and provenance boundaries

- **Strict versus experimental:** the public `integration.run_model` path uses the strict Python mathematical backend. The private investigations repository has a separate, explicitly selected experimental CMD 6.44 mode **only on unmerged draft branches**, with bounded cached/native controls. It is not an automatically selected fallback, a general RORB emulator or an accepted public solver.
- **S5:** the native review can finish successfully as `source_verified_diagnostic` while its ordinate comparison **fails**. Original CMD clock tokens remain intact and the printed native inclusive sample-sum must not be relabelled physical integrated volume. [Native review contract](S5_RECORDED_NATIVE_REVIEW.md).
- **S6:** merged source/method intake, opt-in experimental losses, native excess comparisons and general hydrologic acceptance are distinct. Never treat 42 passing experimental control cells as complete rainfall, loss or routed-flow acceptance. ARR 2026v1, legacy ARR2016/2019 and BoM source profiles remain distinct.
- **Evidence:** the public repository contains source/tests and sanitised summaries, **not** private raw model files, native binaries, source archives, machine paths, or full private comparison tables. The private research repository holds authorised numerical evidence and experiment drafts.

Next actionable tasks (including PR dependency order) are maintained **once** in the [active work register](work/README.md). The dated [S1/S2 readiness handoff](work/2026-11-11-s1-s2-integration-readiness.md) is historical, not the current merge-status authority.
